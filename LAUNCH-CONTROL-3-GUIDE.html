For LC3-only selective feedback, enable CH1–4 EQ/Low, EQ/Mid, EQ/High, Filter1, Filter2, Mute and Cue. The FLX4 needs additional subscriptions.

2 · Use the DAW USB ports

Close other apps holding LC3’s DAW ports. On Windows the documented DAW connection is USB MIDI port 2, not Main.

InputMIDIIN2 (LC3 1 MIDI)
OutputMIDIOUT2 (LC3 1 MIDI)

These are the development machine’s names. Run ap-midi-osc-bridge.exe --list to list yours without sending MIDI. If different, edit inputs / outputs in profiles/launch-control-3.json. Input/output indices are independent; selectors must match uniquely.

Do not select: Main LC3 1 MIDI or an LCXL3 port.

3 · Start the shared bridge

Keep profiles/ beside the current executable. The bridge automatically matches connected controllers to their profiles; absent devices are skipped. Connect only LC3 for LC3-only use. No device-list config or Components remapping is needed.

On Windows, double-click ap-midi-osc-bridge.exe; on macOS/Linux, run ./ap-midi-osc-bridge. No command launcher is needed. Run only one bridge instance.

Startup requests DAW Mixer (EQ), with the Hot Cues button layer and Deck 1. The controller must report a mapped DAW mode before controls become active. No firmware or stored Custom Modes are overwritten.

Modes & encoder pickup

Press/hold Mode and press Function (DAW) to switch DAW Mixer ↔ DAW Control, then exit mode selection. Other device modes are not mapped.

A confirmed change of mode re-arms pickup. AP’s reported EQ/filter positions are sent back to the endless encoders over the DAW output, so they can start from the current value rather than jump blindly. No position feedback → no EQ/filter output.

Function alone toggles the bottom row Hot Cues ↔ Mixer without changing the EQ/filter mode or encoder pickup. Track ◀/▶ selects Deck 1–4 for hot cues, independently of FLX4. The screen shows deck/layer; arrows stop at the ends.

Knobs and Mixer-layer buttons remain fixed to CH1–4, regardless of either controller’s deck selection. These are AP’s main mixer channels, not arrangement-internal trims.

Browser & button behaviour

Top encoder 8: clockwise moves Down; anticlockwise moves Up. The bridge recentres its absolute value after turns for continuous browsing. After a mode change, the first non-echo report establishes a baseline and may consume the first turn.

Matching reports can be suppressed within a 500 ms echo window, including an identical physical report. This is not a MIDI acknowledgment guarantee.

Hot Cues: one tap per press, no held preview. Colours match the supplied Candy Pop palette, but do not show cue existence or follow later AP colour changes. Empty slots can create cues; AP’s existing CueMomentary/Slip settings are not changed. Track routes can act as arrangement markers, not clip/sampler cues.

Mixer-layer Mute / headphone Cue: a press sends the opposite of AP’s confirmed 0/1 state. LEDs follow feedback, not a guessed local toggle. Grey/unknown means the bridge will not guess a switch state.

LC3 has no mapped Browser Enter, Back or Load. Use AP or the FLX4 for those actions.

FILTER ROUTES ARE NOT CONFIRMED.
/AutoPilot/Mixer/CHn/Filter1 and Filter2 are inferred from AP’s 0.1.845 change note and mixer path convention. Missing feedback blocks pickup; feedback alone does not prove the input route is writable.

If controls do nothing

Check the console mode, DAW input and output selection, AP feedback destination/subscriptions, and Browser CONTROL MODE. The bridge does not configure AP for you.

Keep the console open. Ctrl+C requests standalone mode and releases held actions best-effort. Device attach/detach is handled while running; check console errors. Restart after restarting AP or uncertain state. Force-kills and UDP loss cannot guarantee cleanup.
