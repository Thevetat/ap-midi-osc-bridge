Hot-cue colours: fixed Candy Pop RGB palette, NOT populated-cue indicators. Empty slots can set cues. Use the screen for layer identity: Function is purple in Hot Cues and FX, cyan in Mixer. FX action colours: page 3.
Mixer LEDs: red = mute; cyan = headphone cue. Bright/dim follows Syndicate on/off feedback; grey = unknown. EQ/filter knobs are unchanged between Hot Cues and Mixer; FX overrides them.

Modes & encoder pickup

Hold Mode, press Function (DAW) to switch DAW Mixer ↔ DAW Control, then exit mode selection. Other device modes are not mapped. A confirmed mode change re-arms controls. Syndicate feedback synchronizes EQ/filter encoders in Hot Cues/Mixer; no position feedback → no EQ/filter output. FX overrides them in either reported mode and uses dry-home (page 3).

Function alone cycles Hot Cues → Mixer → FX. Switching Hot Cues ↔ Mixer preserves unchanged encoder captures; entering/leaving FX re-arms them. Track ◀/▶ selects the Hot Cue target Deck 1–4 independently of FLX4, stopping at either end. EQ/filter, FX and Mixer buttons stay on main CH1–4, never arrangement trims or cue-selected decks.

Browser & buttons

Top encoder 8: clockwise Down, anticlockwise Up; recentres over DAW MIDI output. After a mode switch, the first non-echo report may establish a baseline. Echo suppression can drop identical physical reports within 500 ms; it is not an acknowledgment.

Cue buttons tap once, no held preview or LC3 cue-region loops. Fixed HotCue hold/SetCueLoop are not mapped. Candy Pop colours do not track later palette/cue changes; empty slots can set cues, CueMomentary/Slip remain untouched, arrangement routes act as markers (not clip/sampler cues). Mixer Mute/Cue buttons invert confirmed 0/1; grey/unknown blocks toggles.

No Browser Enter, Back or Load: use Syndicate or FLX4. /Syndicate/Mixer/CHn/Filter1 and Filter2 are documented in Syndicate §14.9; missing feedback blocks pickup. Hardware/end-to-end operation is unverified.

LAUNCH CONTROL 3 · THIRD FUNCTION LAYER

FX macros

Fixed mixer CH1–4 · both confirmed DAW modes
Static action colours, not FX state
CONFIGURE SYNDICATE FIRST. On each of CH1–4 enable the VST3 insert chain; assign Macro 1 to plugin wet/dry (0 dry → 1 wet), Macro 2 to a mappable plugin enable (0 off, 1 on). Invert a bypass assignment if necessary. The bridge does not toggle the chain or configure the plugin.

Press Function through Hot Cues → Mixer → FX. The screen labels FX CH1–4 and button ON/OFF roles. FX works in either confirmed DAW Mixer (EQ) or DAW Control (filter) hardware mode; while active, it overrides the EQ/filter encoders. Track ◀/▶ still selects a Hot Cue deck, but does not retarget fixed FX channels.

Dry-home safety: There is no documented macro feedback or position pickup. Each time you enter or return to FX, or change the confirmed hardware mode, the first FX-encoder report establishes a baseline only. Then physically turn that encoder to exact 0/dry to send 0 and arm; if it starts dry, nudge away and back. Subsequent motion sends normalized Macro 1 wet. Another known bridge writer, including the FLX4, re-arms dry-home; mouse/external changes cannot be detected.

Buttons 1–4 send Macro 2 = 1; 5–8 send Macro 2 = 0 for CH1–4. Green/red are static action labels, never effect state or confirmation. No macro feedback subscription, fake LED status, or startup/shutdown macro writes. Enable-button writes do not alter Macro 1 wet amount or the entire insert chain.

Other layers: Function to Hot Cues restores EQ/filter encoders in the confirmed hardware mode. Switching Hot Cues ↔ Mixer does not re-arm unchanged encoder bindings; entering/leaving FX does. Browser top encoder 8 works in all layers.

Feedback is change-only since 0.1.902; no rate setting. Blocked takeovers may request a resend after 250 ms, globally at most once/sec; no timeout confirms success. Details.

For selective LC3 subscriptions: CH1–4 EQ/Low, EQ/Mid, EQ/High, Filter1, Filter2, Mute, Cue. FX macros have no documented feedback; FLX4 needs additional subscriptions.

If controls do nothing

Check console mode, DAW input/output, feedback subscriptions/destination and Browser CONTROL MODE. The bridge does not configure Syndicate.

Default profile/wire root: /Syndicate/ (0.1.903+). Custom osc_root must match feedback; update old profiles explicitly. Root rules.

Keep the console open. Ctrl+C attempts standalone mode and held releases, both best-effort, never confirmed. Hotplug is automatic; restart after Syndicate restarts or uncertain state. Force-kills/UDP loss cannot guarantee cleanup.

2 · Use the DAW USB ports

Close other apps holding LC3’s DAW ports. On Windows the documented DAW connection is USB MIDI port 2, not Main.

InputMIDIIN2 (LC3 1 MIDI)
OutputMIDIOUT2 (LC3 1 MIDI)

These are the development machine’s names. Run ap-midi-osc-bridge.exe --list to list yours without sending MIDI. If different, edit inputs / outputs in profiles/launch-control-3.json. Input/output indices are independent; selectors must match uniquely.

Do not select: Main LC3 1 MIDI or an LCXL3 port.

3 · Start the shared bridge

Keep profiles/ beside the current executable. The bridge automatically matches connected controllers to their profiles; absent devices are skipped. Connect only LC3 for LC3-only use. No device-list config or Components remapping is needed.

On Windows, double-click ap-midi-osc-bridge.exe; on macOS/Linux, run ./ap-midi-osc-bridge. No command launcher is needed. Run only one bridge instance.

Startup requests DAW Mixer (EQ), with the Hot Cues button layer and Deck 1. The controller must report a mapped DAW mode before controls become active. No firmware or stored Custom Modes are overwritten.
